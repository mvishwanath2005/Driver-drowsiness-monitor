Spatial Facial Landmark Tracking for Automated Drowsiness DetectionA proactive, non-intrusive, real-time computer vision system for driver safety monitoring.   OverviewFatigue and micro-sleeps are leading causes of severe road accidents. While many existing safety systems rely on vehicular behavior like lane drifting—which only detects danger after focus is lost—this project evaluates the driver's biological state in real-time before an accident occurs.   System ArchitectureThe system processes a continuous video stream from a dashboard-mounted camera through the following pipeline:   Optimization: Converts the video stream to grayscale via OpenCV to improve processing performance.   Detection & Mapping: Isolates the facial region of interest and applies 68-point facial landmark mapping using dlib.   Decision Logic: Continuously calculates eye and mouth metrics against dynamic sensitivity thresholds.   Output: Triggers real-time visual and audio alerts while logging automated events.   Core MathematicsThe system relies on scalar values derived from facial landmark distances rather than complex image processing.   Eye Aspect Ratio (EAR)
EAR measures the state of the driver's eyes. The numerator calculates the vertical distance between the eyelids, while the denominator calculates the horizontal width. As the eye closes, the EAR approaches zero. If the EAR drops below a specific threshold for a set wait time, the system sounds an alarm.
   $$EAR=\frac{\vert{}\vert{}p_2 - p_6\vert{}\vert{} + \vert{}\vert{}p_3 - p_5\vert{}\vert{}}{2\vert{}\vert{}p_1 - p_4\vert{}\vert{}}$$   Mouth Aspect Ratio (MAR)
MAR tracks the spatial relationship of the outer lips to detect yawning, a primary indicator of fatigue. It measures the vertical opening of the mouth relative to its horizontal width. Sustained high MAR values will trigger a yawn alert.
   $$MAR=\frac{\vert{}\vert{}p_3 - p_9\vert{}\vert{} + \vert{}\vert{}p_5 - p_7\vert{}\vert{}}{2\vert{}\vert{}p_1 - p_{11}\vert{}\vert{}}$$   Technologies & FrameworksOpenCV: Handles real-time video capture, image matrix manipulation, and on-screen data rendering.   Dlib: Provides robust, pre-trained HoG (Histogram of Oriented Gradients) face detection and shape prediction.   Python (Tkinter): Powers a multi-threaded, responsive graphical user interface, separating the heavy video processing loop from the UI.   Data Exporting: Utilizes CSV, JSON, and HTML modules for post-session safety analysis.   Key FeaturesLive Metrics: Displays real-time EAR and MAR values alongside a dynamic "Safety Score" gauge.   Adjustable Sensitivity: Includes Low, Normal, and High profiles to account for different lighting conditions and drivers.   Failsafes: Features a "No Driver Detected" auto-pause function to prevent false positives when the camera view is obstructed.   Future ScopeEdge Computing Deployment: Porting the Python backend to run on an embedded device like a Raspberry Pi 5 for self-contained, in-vehicle use.   Hardware Integration: Wiring the alert triggers to physical dashboard buzzers or LED arrays utilizing GPIO pins.   Model Upgrades: Transitioning from the dlib shape predictor to a lightweight Artificial Neural Network (ANN) to improve framerates on resource-constrained edge devices.
